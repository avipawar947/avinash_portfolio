4. RESPONSIVE DESIGN CONTRACT
Mobile rules use max-width:600px; desktop section overrides start at 601px.
The mobile reference width is 393px. The desktop reference width is 1920px;
many original screenshots are exported at double those logical dimensions.
body defines --u as min(.052083333cqw,1px) for desktop and --m as
.254452926cqw for mobile. Dimensions use calc(value * var(--u/--m)).
The main content is capped at 1920px. Test against content width rather than
outer browser-window width; a desktop scrollbar may consume approximately 15px.
Preserve the requested compositions, section order, logo positions and spacing.
Do not turn the whole page or Tools section into a single screenshot.

6. INTERACTIONS AND ACCESSIBILITY
Mobile menu uses a native dialog (#mobile-menu) opened by .menu-toggle.
It is a full-screen, mobile-only panel, not the old compact dropdown.
Home/Work/About/Contact map to #home/#work/#about/#contact. Selecting a link
closes the menu, restores page scrolling and focuses the destination section.
The X button and Escape close the menu and return focus to the menu toggle.
The native modal handles background inertness and keyboard focus containment.
Changing to desktop (>600px) automatically closes the menu and clears scroll lock.
LinkedIn and Download Resume use the same config destinations as the rest of the page.
At 393 x 780: header 80px, logo 117px wide, close circle 40px, navigation rows
120px high, text 40px/48px bold, separators at y200/320/440, actions at y692.
The menu uses --menu-unit:.254452926vw and 100dvh. Shorter screens scroll within
its own panel; all actions stay reachable. Background is a CSS radial gradient.
Reference: references/Ap Menu Screenshots.png.
Case-study cards follow configured URLs; empty destinations open artwork dialogs.
Photos use the currently selected responsive image in the native dialog preview.
Photo strip supports horizontal scrolling and keyboard focus; some older arrow
controls remain in markup but are hidden in the final reference-matched layouts.
Device tabs update aria-selected, tabindex, panel labels and visible mockups.
ArrowLeft/ArrowRight/Home/End work for the device tab group.
Dialogs have close buttons and outside-click handling; native dialog Escape applies.
Navigation active states use IntersectionObserver. Gallery centers on load/resize.
Privacy and Cookies buttons open existing informational dialogs.
Visible focus styling and reduced-motion-aware gallery scrolling are present.

8. RUNNING AND DEPLOYING FROM ANOTHER ACCOUNT
Serve the website folder using a standard static server (see README_FIRST.txt).
For any static host, deploy the CONTENTS of website as the site root and keep
assets relative to index.html. Do not set the ZIP root as the site root.
For Sites-style hosting, hosting/hosting.example.json contains a static directory
configuration without a project ID. A new account must create/select its own site
and use that service's returned ID and credentials. An account-independent ZIP
does not grant access to the old site's repository or existing hosted site.
The current hosted site was owner-private at the last verified publication.
No repository access token, account login, .git history or internal publishing
helper is included in this handover. Do not expect old deployment access to transfer.
If continuing the SAME hosted site, arrange authorized access with the owner first.
Cache query strings on the stylesheet and replacement assets can be incremented
when publishing changes. Keep desktop and mobile asset replacements scoped.
